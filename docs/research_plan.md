# CADloop 研究计划

状态：初始化草案。更新日期：2026-10-16。研究主线已确认是**参数化 3D CAD agent 的工具调用建模与修改**；二维制图、网格生成、装配、GUI 操作与真实工业设计约束暂不自动纳入同一任务。具体任务轨道仍需在 M1 冻结。

## 1. 要研究的对象

本项目关注 agent harness：模型如何读取任务和 CAD 状态、调用建模工具、利用反馈、管理上下文、发现失败并恢复，以及如何在预算内提交结果。

| 层次 | 包含内容 | 本项目如何处理 |
| --- | --- | --- |
| 基础模型 | 模型版本、推理参数、上下文、视觉能力 | 作为独立实验变量；不能把换模型的收益归因于 harness |
| Harness | 规划、工具接口、状态表达、记忆、检查、回滚与重试 | 主要研究对象；先复现可比基线，再逐项消融 |
| CAD 环境 | CAD kernel、脚本/API、文档、导出、观察与几何检查 | 固定版本和能力边界；所有可比 harness 享有相同权限 |
| CAD 生成方法 | 直接预测序列、程序或几何的专用模型 | 仅在输入、输出和训练条件相容时比较；否则作为相关工作 |
| 数据与 benchmark | 原始模型、任务、官方划分、评测器与榜单规则 | 数据集不自动等于 agent benchmark；新建任务必须标为本地协议 |

当前的 mock smoke 仅用于验证任务读取、执行、检查、轨迹和结果存储的工程链路。它使用合成 primitive 参数与标量几何检查，没有真实 CAD kernel 或 LLM；其结果不能用作论文实验或公开榜单分数。

## 2. 初始研究问题与可证伪假设

| 编号 | 研究问题 | 候选假设 | 首个验证实验 |
| --- | --- | --- | --- |
| RQ1 | 相同模型和预算下，几何状态反馈能否提高任务完成率？ | 对可观测几何错误，结构化反馈比仅提供执行异常更有效 | 固定工具和模型，比较无反馈、异常反馈、几何反馈 |
| RQ2 | 检查点与局部恢复能否减少无效重建？ | 编辑任务中，失败后回滚与局部修改比从头重写节省调用和费用 | 比较完整重写与局部恢复，并计入检查、重试成本 |
| RQ3 | 收益能否跨模型、任务复杂度和 CAD 表示迁移？ | 方法收益并非只出现在单模型或简单 primitive 上 | 至少两个模型、多个复杂度分组；预算允许后再做第二环境 |
| RQ4 | 有效几何是否也满足设计意图与编辑要求？ | 仅优化可执行率不足以提高约束满足率 | 同时报告执行、几何有效、任务约束和编辑保持指标 |

上述均为待检验假设，当前没有结果支持。若收益仅来自更多重试、额外 token 或测试集调参，应缩小结论或停止该方向。

## 3. 候选与来源登记

下面只确认一手资料可读及其描述的用途；尚未冻结版本、下载数据、复现论文结果或核验最新排名。核验日期为 2026-10-16。README 和官网内容会变化，正式复现前必须保存 commit、原文快照和许可证。

| 候选 | 类别与初步用途 | 一手来源 | 已核验范围与待办 |
| --- | --- | --- | --- |
| SWE-agent / mini-SWE-agent | 通用编码 agent harness；研究工具接口与执行循环 | [SWE-agent 官方仓库](https://github.com/SWE-agent/SWE-agent)、[mini-SWE-agent 官方仓库](https://github.com/SWE-agent/mini-swe-agent) | 已读 SWE-agent README，确认提供通用工具任务，且 README 将后续开发指向 mini-SWE-agent；待确定具体复现对象、固定 commit、模型配置与 CAD 适配边界；不据此认定 CAD SOTA |
| OpenHands Software Agent SDK | 通用 agent SDK；候选工具、事件、工作区和会话基线 | [官方 SDK 仓库](https://github.com/OpenHands/software-agent-sdk)、[官方文档](https://docs.openhands.dev/sdk) | 已读官方 README，确认 SDK 管理 agent、工具、工作区与事件；当前 OpenHands 主仓库还涉及界面和编排，不能混用版本；待确定论文对应实现、commit 与运行成本 |
| DeepCAD | CAD 生成方法、序列表示与数据候选 | [官方代码](https://github.com/rundiwu/DeepCAD)、[论文](https://arxiv.org/abs/2105.09492) | 已读 README，确认 construction sequence、重建/生成评测与 OpenCASCADE 依赖；待核验代码/数据许可证、划分、去重、表示能力和环境兼容性；不是现成的交互式 agent benchmark |
| Fusion 360 Gallery | 人类建模序列、重建环境与数据候选 | [官方仓库](https://github.com/AutodeskAILab/Fusion360GalleryDataset)、[重建论文](https://arxiv.org/abs/2010.02392) | 已读 README，确认 reconstruction、segmentation、assembly 是不同子集；待阅读 reconstruction 协议、许可证、Fusion API 可运行条件与固定划分；不合并子集分数 |
| ABC | CAD 几何数据与去重/几何评测资料候选 | [官方项目页](https://deep-geometry.github.io/abc-dataset/)、[官方仓库](https://github.com/deep-geometry/abc-dataset) | 已读项目页，确认多种几何格式及其法向估计 benchmark；待核验许可、来源分组、可用性和参数化序列适配性；法向估计分数不作为 agent 建模成绩 |

补充相关工作：[Text2CAD 官方仓库](https://github.com/SadilKhan/Text2CAD) 与[论文](https://arxiv.org/abs/2409.17106)的 README 已读，确认其文本到 CAD 序列方法与 DeepCAD 数据依赖。后续可作为文本条件任务候选，但其生成模型与工具交互 harness 的训练条件不同，不能直接放进同一公平比较表。许可证、测试集和版本仍待核验。

**尚未完成的调研**：筛选目前真正面向 CAD agent 的公开 benchmark、官方榜单和领域专用 harness，核对论文、官方代码、评测服务、提交规则及最近更新时间。在这一步完成前，不使用“当前 SOTA”“主流 benchmark 已覆盖”或“成功复现”的表述。

## 4. 分阶段里程碑

以依赖关系推进，周数仅为粗略工作量估计，不是承诺工期。

| 阶段 | 目标与交付物 | 通过条件 | 失败时的动作 |
| --- | --- | --- | --- |
| M0：项目骨架（当前） | 文档、配置、mock smoke、轨迹与报告约定 | 新环境可用文档命令跑通 smoke；产物明确标识 mock | 修复工程链路，禁止用 smoke 数值包装论文结果 |
| M1：问题与来源冻结（约 1 周） | 相关工作表、首个任务轨道、官方来源、许可与数据清单 | 选定至少一套可合法获取且有确定评价规则的真实任务；明确两种 harness 基线 | 获取失败则替换候选并记录原因；未确认许可不发布数据 |
| M2：真实 CAD 闭环（约 1–2 周） | 一种 CAD 环境、确定性回放、几何检查、最小建模/编辑任务 | 固定环境能执行与验证有效/无效/恢复示例；每个任务从干净状态启动 | 简化工具集，定位内核、表示或任务定义问题 |
| M3：基线与复现（约 2–3 周） | 原始协议复现记录、CAD 适配基线、固定 dev manifest | 至少两个可比基线完整记录预算和失败；能解释与原文的差异 | 无法复现时公开差异，保留 adapted baseline 标签 |
| M4：方法与消融（约 2–4 周） | 自有 harness、组件消融、开发集预算曲线 | 相同模型/预算下有可重复收益；收益覆盖代表性任务而非少数特例 | 缩小假设或重新设计；不能凭个别成功案例宣称优势 |
| M5：冻结评测与论文（约 1–2 周） | 冻结 test 评测、置信区间、完整失败分析、论文初稿 | 配置/commit/manifest/评测器齐全，可从原始轨迹重算表格 | 修复评测缺陷后按新版本整体重跑，保留旧版本记录 |
| M6：榜单提交与开源 | 官方格式产物、运行说明、可发布数据/代码清单 | 符合目标榜单规则，作者信息、训练披露和提交内容已检查 | 无公开榜单时只发布本地协议结果，不称官方排名 |
