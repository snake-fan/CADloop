# 复现与评测协议

状态：研究协议草案，2026-10-16。当前只有 mock smoke 工程验证；没有真实 CAD benchmark 成绩，没有已完成的 SOTA 复现。本文件约束未来实验记录；这里的字段不代表当前代码已经实现全部能力。

## 1. 三种实验必须分别命名

| 标签 | 含义 | 允许的结论 |
| --- | --- | --- |
| `official_reproduction` | 固定论文对应代码、任务、模型、配置、划分和原评测器；显式记录例外 | 在明确误差和资源范围内是否复现原文结果 |
| `cad_adaptation` | 将通用 harness 或 CAD 方法适配到新的工具/任务 | 该适配版本在本项目指定协议下的结果 |
| `local_protocol` | 本地新建或从数据集派生的 CAD 任务 | 本地协议结果；不等同官方 benchmark 或公开榜单 |

仅阅读论文、安装成功、跑通一个示例或完成 mock smoke 都不等于结果复现。论文使用的旧版本与仓库当前主分支也不能自动视为同一方法。

## 2. 任务轨道与可比性

至少分别处理文本建模、视觉重建、指令编辑；是否加入装配或 GUI 操作由研究计划另定。每条轨道固定输入、初始文档、输出表示、工具集、允许的反馈、单位和几何容差。编辑任务还要定义保留哪些未编辑特征。

只有 benchmark 版本、划分、任务输入、工具权限、模型访问和预算均相容的结果才进入同一比较表。公开协议优先使用官方评测器；改动任务或评测器时建立新的协议版本。不同数据集、重建与编辑、专用生成模型与通用 agent 不产生一个混合总排名。

## 3. 每次运行前冻结的清单

| 类别 | 必须记录 |
| --- | --- |
| 代码与依赖 | 本仓库 commit、基线原始 commit、适配 patch、Python/系统版本、依赖锁文件、容器摘要（若有） |
| CAD 环境 | kernel 与 API 版本、工具 schema 哈希、单位/坐标系、公差、渲染配置、几何检查器与导出设置 |
| 模型 | provider、完整模型 ID/快照、访问日期、采样参数、上下文限制、视觉设置、provider 是否支持 seed |
| Prompt 与上下文 | system/user prompt 哈希、示例、工具描述、记忆/压缩规则、检索库和可访问文档 |
| 数据 | 原始来源与版本、下载校验和、许可证状态、任务 manifest 哈希、split、预处理脚本与过滤原因 |
| 预算 | 总 token/费用、模型请求、工具调用、墙钟上限、并发、候选数、检查与重试上限；预算判定的计费边界 |
| 随机性 | 数据抽样 seed、agent seed、模型 seed（若支持）、调度 seed；不支持的项写明 `unsupported` |
| 结果身份 | run ID、协议版本、轨道、实验标签、原始日志位置、汇总器版本 |

不要将 API 密钥写入配置、prompt、trace 或论文附件。缓存命中、隐藏的自动重试、上下文压缩与失败请求也计入预算或明确单独记录。价格变化时保存计价日期和单价，避免把当前价格回填历史实验。

## 4. 数据划分与防止测试集调参

1. 首选官方 train/dev/test 划分。缺少官方划分时，在看模型测试结果之前冻结本地分组划分，并标记 `local_protocol`。
2. 按设计来源/文档 ID 分组检查重复和近似变体；一个 CAD 模型的不同渲染、文字描述、尺寸变体不能随意跨 dev/test。
3. 允许在 dev 上调整工具、prompt、公差与恢复策略，记录尝试次数和开发成本。冻结后只做预先声明的 test 评测。
4. 测试期间发现数据或评测器错误时，记录受影响样本和版本；修正协议后对所有比较方法一致重算/重跑。
5. 未知训练数据污染风险作为限制披露。能确认的训练交集应记录；不能用“未发现”推断“无污染”。

## 5. 控制变量与预算

主实验固定基础模型、采样参数、CAD 环境、可用工具、任务顺序和预算，只改变 harness。第二组实验固定 harness 比较模型，避免混淆归因。

预算比较至少给出任务成功率随费用或 token/工具调用上限变化的曲线。检查、规划、恢复、候选筛选、失败重试都消耗预算；所有方法都使用同样的截止规则。模型未提供可比 token 统计时，保留原始计量并以费用/请求/墙钟作补充，不强行统一。

随机方法初步计划使用 3 个独立运行 seed；正式次数按 pilot 方差和可用预算确定，并在 test 前冻结。每个 seed 先完整评价固定任务集合，再汇总均值与方差；不要仅展示最佳 seed。provider 不保证随机种子时记录独立重复调用，不能宣称位级可复现。

## 6. 指标与方向

官方 benchmark 的指标、归一化、公差和采样规则优先；下列为本地 CAD 轨道的候选定义，不是当前实现声明。

| 指标 | 方向 | 定义与必要限制 |
| --- | --- | --- |
| 任务成功率 | ↑ | 完成全部预声明设计约束的任务数 / 全部任务数；无效几何不能算成功 |
| 执行成功率 | ↑ | 工具链完成且产物可读取；只表示可执行，不代表满足设计意图 |
| 几何有效率 | ↑ | 由固定 kernel/checker 判定满足预声明的实体/拓扑有效性；保留检查失败原因 |
| 约束满足率 | ↑ | 固定尺寸、相对关系或特征检查的满足比例；同时给出全部约束同时满足率 |
| 几何距离 | ↓ | 如采用 Chamfer distance，必须固定单位、尺度归一化、表面采样、点数和距离形式；不能只在成功子集上隐去失败 |
| 编辑保持率 | ↑ | 编辑后满足未编辑特征保持要求的比例；具体特征与容差在任务卡冻结 |
| 成本与耗时 | ↓ | token、费用、请求数、工具调用数、墙钟；分别报告全体任务均值和成功任务成本 |
| 预算内成功率 | ↑ | 在指定预算截止前提交有效且满足约束的结果比例；若报告 pass@k，固定 k、候选相关性与总预算 |

几何距离对无产物/无效产物可能未定义。应同时报告全任务成功/失败和距离可计算覆盖率；如需失败惩罚，提前冻结有限上限与理由。禁止悄悄删除失败样本后只比较距离。

## 7. 失败分类与重试

每个任务最终只有一个终态，失败仍保留在分母中：`success`、`constraint_failure`、`invalid_geometry`、`execution_error`、`budget_exhausted`、`timeout`、`infrastructure_error`。正式实现可以扩展细项，但必须保持可映射的稳定语义。

- 输出解析失败、模型生成错误、建模异常、几何无效、越界调用与耗尽恢复次数属于方法失败；不自动排除。
- provider 服务故障、机器中断、损坏的数据下载等属于候选基础设施失败；保留首次记录，只按预先冻结、对所有方法一致的规则重跑。
- 恢复重试属于同一次任务预算。基础设施重跑与模型自己尝试多个候选分别记账；保留 attempt ID，不能覆盖失败轨迹。
- 人工辅助任务不得混入自动成绩；保留诊断记录并单独标记。

## 8. Trace、统计与审计

每个 task/attempt 保留初始输入、公开可见观察、模型请求/响应、工具参数、结果或异常、状态摘要、预算余额、最终 CAD 产物路径与校验和，以及独立 evaluator 的原始判定。trace 应足以解释最终状态；导出前去除密钥、用户隐私与不具发布权的材料。

配对比较使用相同任务和 seed/重复轮次。报告样本数、均值、跨 seed 离散程度和任务级配对差值；预先指定置信区间方法（如按任务分组的 paired bootstrap）。同源模型的多个渲染不是独立样本。多方法、多消融比较要说明探索性分析范围，不仅报告显著的部分。

为每个候选建立独立记录，按以下状态推进：`candidate → source_verified → environment_ready → smoke_passed → evaluation_complete → audited`。阻塞可写为 `blocked` 并保留原因，不跳过阶段。
